# Финальное code review перед конкурсом · 21.10.2026

Продуктовые функции и проверенные идентификаторы ЦБ не менялись.

## Найдено и исправлено

1. Длительная Prisma transaction охватывала HTTP и нормализацию (до 30 минут).
   Получение данных вынесено наружу. В БД выполняются только короткие транзакции
   получения владения, атомарной записи или фиксации ошибки.
2. Создание/восстановление SyncLog через `this.db` внутри `$transaction` нарушало
   границы атомарности. Все связанные операции теперь выполняются через `tx`.
3. Простой перенос HTTP наружу убрал бы межпроцессную защиту advisory xact lock.
   Добавлен срок владения в SyncLog, heartbeat по времени PostgreSQL и единственный
   RUNNING, обеспеченный частичным уникальным индексом. Перед записью проверяется
   владение с блокировкой строки. Старый владелец после перехвата не может писать.
4. Проверены SUCCESS/PARTIAL/FAILED, полный HTTP-сбой, пустой результат,
   настоящий SQL overflow с rollback, истечение владения, авария отдельного процесса.
   При полном отказе БД невозможно синхронно записать FAILED: исходная ошибка и ошибка
   завершения лога сохраняются в AggregateError, затем срабатывает восстановление.
5. Docker shell/npm могли мешать доставке SIGTERM. Node запускается через `exec`
   как PID 1; задано 45 секунд для штатного завершения.
6. Интеграционные тесты зависели от уже импортированных данных приложения.
   Теперь используют отдельные временные схемы и реальные сохранённые fixtures.
7. Уточнены исключения Git/Docker; добавлен проверяемый ZIP исходников с явным
   списком файлов. package-lock.json сохраняется и проверяется по SHA-256.

## Механизм блокировки

Короткие claim/write транзакции используют общий advisory lock в пространстве схемы.
Внешний HTTP не держит транзакцию, row lock или выделенное соединение.
RUNNING продлевается раз в 10 секунд; срок — 60 секунд. При записи владелец блокирует
строку до commit/rollback, поэтому даже истечение срока во время записи не допускает
второго импорта. Это относится к ручным вызовам, scheduler и другим процессам.
Поведение транзакционных advisory/row locks соответствует
[документации PostgreSQL 17](https://www.postgresql.org/docs/17/explicit-locking.html).

Восстановление аварии происходит при следующем запуске после истечения срока.
При остановке БД или длительной паузе процесса старый запуск утрачивает право записи.
Оставшийся HTTP может завершиться позже, но его результат уже не попадёт в БД.

## Проверка

Регрессии запускаются через `npm run test:integration`, с настоящим PostgreSQL,
включая два OS-процесса и принудительное завершение одного из них. Каждый прогон
создаёт и удаляет только свои схемы `review_<uuid>`.
Основные команды: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`,
`docker compose up --build`, `npm run smoke -- --sync`.

Фактически успешно прошли `typecheck`, `lint`, все 14 unit-тестов, production build
и `format:check`. Все 9 интеграционных тестов прошли на хосте и внутри backend-контейнера.
`docker compose up --build -d` собрал/запустил проект; PostgreSQL и backend healthy.
HTTP smoke подтвердил frontend HTML/JS, прокси nginx, `/health`, все шесть OpenAPI
endpoints, данные четырёх регионов; отдельно проверены HTML Swagger и его JS bundle.

Для проверки первичного импорта создан отдельный Compose-проект с **новыми** volumes
и портами 55433/3002/8081, на тех же собранных образах. Первый живой импорт:
`SUCCESS`, Received=1280, Inserted=480, Updated=0, Skipped=800. Повторный:
`SUCCESS`, Inserted=0, Updated=0, Skipped=1280; число наблюдений осталось 480.
Проверены все ключи `(region, period, metric)` — дубли отсутствуют. Временный стенд
удалён вместе с его тестовыми volumes; основная БД сохранена. Node штатно обработал
SIGTERM и завершился с кодом 0.

Git-правила проверены через `git check-ignore`: локальные артефакты исключены,
package-lock.json, `.env.example`, curated samples/evidence сохраняются.
ZIP проверяет собственный состав и совпадение SHA-256 lockfile с исходным.

## Оставшиеся ограничения

- Четыре настроенных разреза; полное региональное/историческое покрытие не заявляется.
- Восстановление после crash отложено до истечения владения и следующего запуска.
- Полностью недоступная БД не позволяет немедленно завершить лог в этой БД.
- Время атомарной записи ограничено 30 секундами; проверено на текущем объёме MVP.
- Визуальные браузерные тесты отсутствуют; проверка frontend — сборка, HTML/JS и HTTP.
- Административный sync без авторизации допустим только в текущей локальной демонстрации.
- XLSX fallback и расширение банковского сектора вне шести метрик не реализованы.
