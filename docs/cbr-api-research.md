# Этап 1: исследование Data Service API Банка России

Проверка выполнена **20 октября 2026 года**. Все указанные ниже ID сначала получены
из действующего API, затем проверены диагностическим CLI. Скрипт не содержит
зашитых ипотечных ID и заново валидирует выбранные значения по живым справочникам.

## Источники

- [Официальная документация](https://www.cbr.ru/statistics/data-service/APIdocumentation/).
- [Официальная OpenAPI 3.0.3, версия сервиса 1.0](https://www.cbr.ru/dataservice/swagger).
- [Официальные примеры Python и C#](https://www.cbr.ru/statistics/data-service/APIdocumentation/examples/).
- [Живой каталог publications](https://www.cbr.ru/dataservice/publications).
- [Живой каталог ипотечных datasets](https://www.cbr.ru/dataservice/datasets?publicationId=21).

Проверенная цепочка: `publications → datasets → measures (если type=1) → years → data`.
Дополнительно проверены `datasetsEx` и `DatasetDescription`. Методы `dataEx`,
`yearsEx`, `categoryNew`, `dataNew` присутствуют в OpenAPI, но запросы к ним
в рамках этапа 1 не выполнялись; совместимость их ответов с будущим mapper не заявляется.

## Фактические ответы /data

Все семь тестовых запросов использовали `y1=2026&y2=2026` и вернули HTTP 200,
`periodicity="month"`. Получены месяцы **январь–август 2026**, то есть восемь месяцев,
а не полный год. Количество/объём/остатки содержат по 24 строки (три валютных столбца),
срок и ставки — по 16 (два столбца). Порядок строк не хронологический: например,
валютные столбцы одного месяца могут идти в другом порядке.

Форма `/data` подтверждена: объект с `RawData`, `headerData`, `units`, `DTRange`,

`rowId`, `dt`, `periodicity`, `date`, `digits`.
CLI сохраняет весь ответ, включая поля, не используемые его проверками.

## Критические особенности для следующего этапа

1. **Месяц и дата различаются.** Для количества `dt="Январь 2026"`,
   `date="2026-02-01T00:00:00"`. В методологии количества явно сказано: показатель
   формируется за отчётный период (месяц). Для объёма, срока и ставки в проверенных
   строках наблюдается такое же соответствие. Нельзя брать месяц из `date`
   без правила преобразования и проверки согласованности с `dt`.
2. **Остатки имеют другую семантику.** У задолженности и просрочки `reporting="date"`,
   `dt="01.02.2026               "`, `date="2026-02-01T00:00:00"`.
   Это состояние на дату. Для общей месячной таблицы нужно явно определить,
   как относить остаток на 1 февраля к концу января, сохранив исходную дату.
   Автоматически применять правило выдач ко всем показателям нельзя.
3. **Валютные столбцы нельзя суммировать вместе.** Для количества, объёма, задолженности
   и просрочки `headerData`: 35 «Всего», 36 «В рублях», 40 «В иностранной валюте».
   Срок и ставка содержат только 36 и 40; общего столбца у них в полученных ответах нет.
   Для сопоставимой аналитики разумно выбрать рублёвые выдачи и явно подписать валюту;
   это предложение для этапа 2, а не выполненная нормализация.
4. **`units` — общий справочник.** Он содержит десять единиц даже в ответе,
   где используется только одна. Преобразование определяется `RawData[].unit_id`:
   объём и долг в млн руб.; для суммы в рублях понадобится множитель 1 000 000.
   Средний размер кредита должен учитывать этот множитель. Срок — в месяцах.
5. **ID разреза не является кодом региона РФ.** 22 означает РФ, 41 — Москву,
   33 — Московскую область. Иерархия включает страну, федеральные округа, субъекты
   и специальные агрегаты, например Тюменскую область с/без автономных округов.
   Нельзя суммировать все элементы справочника или трактовать их как субъекты одного уровня.
6. **`NoActive` имеет значение.** `publications` включает разделы (`NoActive=1`),
   не выбираемые как публикации с данными. Часть полей из OpenAPI, например
   `pub_description` и `updated_time`, отсутствует в живом ответе publications.
7. **История зависит от запроса.** Для количества РФ `/years` вернул 2019–2026,
   для ставки РФ — 2017–2026, для ставки Москвы — 2019–2026.
   При этом `datasetsEx` публикации 21 указывает общий диапазон 2009–2026.
   Общий диапазон публикации нельзя считать доступностью конкретного ряда.
8. **`type != 1` не требует measures.** На ставке РФ 29 это проверено живым запросом:
   `/years` и `/data` работают без `measureId`. Для региональной ставки 34 выбирается
   обычный разрез, проверенный через `/measures`.

## Ограничения и неподтверждённое

- Полное покрытие всех 96 разрезов данными по всем шести показателям не проверено.
  Наличие элемента в справочнике не гарантирует непустой ряд.
- Исторические годы и смены методологии на всём горизонте пока не проверены.
  Снимки охватывают только доступную часть 2026 года.
- Нулевая ставка/срок в валютном столбце требует отдельной проверки методологии:
  отсутствие выдач нельзя автоматически интерпретировать как реальную нулевую ставку.
- У строк `/data` нет отдельно подтверждённого времени обновления наблюдения;
  время обновления `dataset` не следует выдавать за точное время ревизии каждой строки.
- Не установлен гарантированный график публикаций, SLA и rate limit. Ежедневный
  scheduler с месячными рядами остаётся решением приложения, а не свойством API.
- XLSX fallback не понадобился: все шесть целевых показателей найдены через REST.
  Его загрузка и парсинг пока не реализованы.
- Прямой запрос через Windows curl сначала завершался
  `CRYPT_E_REVOCATION_OFFLINE`; Node.js с обычной проверкой TLS успешно работает.
  Отключение TLS-проверки не использовалось.
- В OneDrive наблюдалась временная ошибка `EPERM` при замене файла manifest.
  Добавлен ограниченный повтор атомарного переименования; повторная проверка прошла.

Этап 1 завершён: CLI запускается, восемь обязательных действий диагностики выполнены
на реальном источнике. Результат готов для фиксации правил доменного отображения
и дальнейшей реализации адаптера, без предположений о неизвестных ID или форме ответа.
